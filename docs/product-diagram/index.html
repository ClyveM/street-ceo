STREET CEO / CONNECTED DEMO MVP

From spoken basket to saved sale.

A practical counter assistant. Voice when your hands are busy; typing when you need it.

The shopkeeper’s path

  1. Catalogue. Saved product names, prices, stock and quantities. Starter costs are illustrative.
  2. Manual or Apo. Tap/type, or say “Apo one Coke Napo.” Unknown products never become a partial basket.
  3. Cash or Bank. Ask for cash received; verify total and change. Bank is recorded tender, not settlement.
  4. Sale saved. Only after a durable receipt: Total, Tendered, Change. Refresh stock/history. Say Apo for the next sale.

Suggestions require Yes. Local or Muse proposals need approval before payment. Missing quantity asks again. Unknown products are spoken. Uncertain paid requests keep the original basket and retry key.

How the connected demo works

  1. Android APK + web UI handles foreground speech, pauses recognition during spoken output, and supports typing.
  2. HTTP over the local network → FastAPI. The server validates catalogue, approval, totals, stock and idempotency.
  3. FastAPI → SQLite transaction. Saves catalogue, sales, stock, reviews and original retry bindings on the API host.
  4. Unresolved phrases → Muse. One short bounded wait; actual provider calls labelled honestly. Every proposed match still requires Yes.
  5. Sanitized persistent investigations. Requests, responses and failures retain correlation and provider provenance.

Connected demo: the phone must reach the API host. SQLite is on that host, not an offline phone database. Offline sync and PostgreSQL deployment are deferred.

Source: current demo acceptance and implemented client/API contracts. 2 November 2026. This is a schematic, not physical phone test evidence.
